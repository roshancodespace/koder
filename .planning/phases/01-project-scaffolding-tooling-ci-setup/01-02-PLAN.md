Bootstrap the independent VS Code extension in vscode-extension/ using TypeScript ~5.8 and the official VS Code Extension API (^1.90.0). Establish the extension entry point with activation hooks and a status bar indicator, configure strict TypeScript compilation and ESLint code quality tooling, provide an automated test runner harness, enforce .vscodeignore packaging boundaries, and configure an independent GitHub Actions CI workflow for automated linting, compilation, headless testing, and VSIX packaging verification.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Extension Manifest -> VS Code Host Runtime | Extension activation hooks and permissions registered with the VS Code extension host. |
| Extension Package Artifact -> Public Distribution | Compiled VSIX bundle must not leak development files, secrets, or unverified dependencies. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Elevation of Privilege | vscode-extension/package.json | medium | mitigate | Restrict activationEvents to onStartupFinished and explicit command triggers; avoid wildcard (*) activation to prevent resource leaks and unauthorized early execution. |
| T-01-04 | Information Disclosure | vscode-extension/.vscodeignore | low | mitigate | Enforce strict .vscodeignore exclusions so development source files, test harnesses, CI configurations, and local credentials are omitted from the packaged VSIX artifact. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS] (Extension dependencies restricted to official Microsoft @vscode/* tooling, types packages, and verified ws library). |
</threat_model>
